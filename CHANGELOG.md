# Changelog

All notable changes to Azure.Admin.Console. Versions before 0.10.0 were never published to the PowerShell Gallery.

## v0.14.6

Governance across the tenant in the spirit of the Azure Governance Visualizer - eleven new commands and one workbook - Service Bus and Cosmos DB assessments, editable draw.io diagrams of what you have, existing resources exported as Terraform, and a dashboard that now covers security, policy, governance, cost and what to do next. Published as a pre-release (0.14.6-preview1) first.

### New

- **Service Bus assessment.** `Invoke-AACServiceBusAssessment`: every namespace's requests, errors and throttling, Premium CPU and memory, and every queue, topic and subscription's messages as they are now - active, dead-lettered, transfer dead-lettered, scheduled, how full it is, when it was last used; findings under health, capacity, messages, security, resilience and cost (dead letters, entities filling up, backlogs, topics with no subscription, SAS keys, open networks, no logs, no zones or Geo-DR, idle entities, too many messaging units), a heat map, and `-View Namespace|Entity|Finding`.
- **Cosmos DB assessment.** `Invoke-AACCosmosDBAssessment`, for every API (NoSQL, MongoDB, Cassandra, Gremlin, Table): availability, requests by status and rate limiting (429), request units and the busiest partition, latency, storage, every database and container with its throughput (autoscale, manual, shared, serverless); findings under availability, throttling, errors, security, resilience and cost (single region, no failover, periodic backup, open networks, account keys, over-provisioned throughput, many small containers with their own throughput), a heat map, and `-View Account|Container|Finding`.
- **Terraform export.** `Export-AACTerraform` exports existing resources as Terraform through the Azure Export for Terraform API (2026-09-01-preview):
  - a resource group (several in one subscription exported together, with their child resources), resource IDs - or anything piped with an `Id` or `ResourceId` - or a Resource Graph where-clause; a folder per subscription;
  - the export is a long-running operation: submitted, polled as Azure asks (`Retry-After`), with Azure's reason when it fails; each export shows its status, how long it has run and how many batches are done (Azure gives no percentage);
  - large exports: the resources are counted first (Resource Graph), with advice when an export is large; `-BatchSize` splits it into exports that run at the same time (`-ThrottleLimit`) and merges them into one folder - a resource two batches return is kept once, and references to it follow; several subscriptions are exported at the same time;
  - `-Resume`: the operations are saved in `export.json` as soon as Azure accepts them, so an export still running after Ctrl+C or `-TimeoutMinutes` is collected later without exporting again;
  - a folder ready for `terraform init` and `plan`: `terraform.tf`, `providers.tf` (with the subscription ID), `main.tf`, `import.tf` (import blocks - no `terraform import` to run) and `export.json`;
  - what couldn't be exported is listed, never dropped; `-FallbackToAzApi` exports what azurerm can't again with the azapi provider, merged into one module (`azapi.tf`);
  - `-Plan` runs `terraform init`, `validate` and `plan` and reads the plan as `Get-AACTerraformPlan` does: a faithful export plans only imports, anything else is listed;
  - sensitive values masked unless `-IncludeSensitive`; existing Terraform files not overwritten without `-Force`; `-RegisterProvider` registers `Microsoft.AzureTerraform` where it isn't (asks first, honours `-WhatIf`).
- **Editable diagrams.** `Export-AACDiagram` draws your existing resources as a draw.io diagram you can edit - not a picture:
  - four views: `Resources` (resource groups or subscriptions, with network links, peerings, private endpoints, routes, DNS links and dependencies), `Network` (hubs and spokes, gateways, firewalls), `ApplicationGateway` (each gateway's flow) and `Governance` (the management group hierarchy);
  - boxes are draw.io containers; resources carry the Azure icons, their data and a portal link; connections stay attached when you move things;
  - `-Update` refreshes the diagram from Azure and keeps your edits: new resources are added and marked, removed ones faded (`-Prune` deletes them);
  - `-SplitBy` puts each subscription, resource group, management group, region or gateway on its own page; a Legend page explains the boxes and lines;
  - `-HtmlPath` and `-PdfPath` write a clean copy with a legend: an interactive page, and a one-page vector PDF drawn by Microsoft Edge or Google Chrome.
- **Governance**, each question a command of its own:
  - `Invoke-AACGovernanceAssessment`: the hierarchy, access, identities, policy remediation, limits, settings, tags, locks and changes in one tabbed workbook, with the high and medium findings of every area; `-MarkdownPath` writes it as a wiki page (GitHub or Azure DevOps) with the hierarchy as a Mermaid diagram.
  - `Show-AACManagementGroupMap`: the management group hierarchy as an interactive map and a console tree, with the subscriptions, policy and role assignments at each level.
  - `Get-AACRoleAssignment`: every role assignment at every scope - user, guest, group, application or another tenant's, system- or user-assigned identity, deleted - what the role can do, how far it reaches, standing or PIM, group members (`-ExpandGroup`), who created it; orphaned assignments, privileged guests, applications as Owner and custom roles unused or equivalent to Owner flagged.
  - `Get-AACServicePrincipalInsight`: applications and managed identities with Azure roles, their credentials about to expire, other tenants' applications, user-assigned identities attached to nothing or shared too widely.
  - `Test-AACAzureLimit`: scopes close to an Azure limit - role assignments, custom roles, policy assignments, definitions, initiatives and exemptions, resource groups, tags, management group depth - with what to do; `-Maximum` for a raised limit, `-FailOnLimit` for a pipeline gate.
  - `Get-AACGovernanceSetting`: who can create management groups, where new subscriptions land, management group activity logs, Defender security contacts, classic administrators, preview features, resource providers registered unevenly, each subscription's offer and state.
  - `Get-AACPolicyRemediation`: DeployIfNotExists and Modify policies with resources they could fix, and what their remediation tasks did - never run, failed, drifted again, or no identity to run with.
  - `Get-AACTagUsage`: tag coverage and consistency - names that clash in casing, near-duplicates, values in mixed casing, how far `-RequiredTag` reaches.
  - `Get-AACResourceLock`: every lock, the critical resources no lock protects, and ReadOnly locks that break more than they protect.
  - `Get-AACGovernanceChange`: policy and access created or updated in the last days, with the author resolved and privileged grants flagged.
  - `Test-AACAlzPolicy`: your management groups' policy assignments against the Azure Landing Zones archetypes (a local copy of the ALZ Library) - missing, different or present, and the library file to deploy from.

### Changed

- `Show-AACDashboard` - the second edition, from the same single Resource Graph batch (24 queries instead of 8):
  - an Estate score (0-100) from availability, secure score, policy compliance and the Advisor score, and a second row of score tiles;
  - Security (secure score, alerts and recommendations by severity, Defender plans), Governance (policy compliance, the closest role assignment limit, privileged role assignments, unused disks, public IPs and NICs, tag coverage), Advisor savings, resources by type and subscription, the last 14 days of changes and who made them;
  - `-IncludeCost`: month to date against the same days last month, a forecast, 30 days and what costs most (Cost Management);
  - What to do next: the actions that matter most, ranked across every section, each with the command that goes deeper (`.Actions` returns them);
  - `-Section` shows only some sections; `-HtmlPath`, `-PdfPath` and `-CsvPath` write it as a report with a tab per section; `-Watch` refreshes it for a screen on the wall.
  - Every property of `AAC.Dashboard` is still there; the status also turns to Needs attention for high-severity security alerts, policy compliance below 80%, a subscription at 80% of the role assignment limit, or spend more than 10% above last month.
- The browser maps (`Show-AACResourceMap`, `Show-AACNetworkTopology`, `Show-AACApplicationGatewayMap`): a **draw.io** button saves the map as an editable diagram exactly as laid out; the legend now explains the boxes too (subscription, resource group, virtual network, hub, subnet, Application Gateway) and the resource flags; "Open in the Azure portal" sits at the top of a resource's details.
- `Show-AACResourceMap`, `Show-AACNetworkTopology` and `Show-AACApplicationGatewayMap` read Azure through shared readers, the same ones the diagrams use (no change to what they show).
- `Invoke-AACArmWrite` (the module's write helper) runs POST actions too and returns their result; the new `Invoke-AACArmOperationBatch` runs several long-running operations side by side.
- `Get-AACServicePrincipalInsight` asks Microsoft Graph for the app registrations in a fixed order, so the same principals always make the same requests.
- The tests run on **Pester 6.2+** (below 7) instead of Pester 5: `build.ps1`, CI and the release workflow install and require it, and `build.ps1 -Task Test` says what to install when it's missing. Pester 6 needs PowerShell 7.4 or later to run the tests; the module itself still runs on 7.2. The test files needed no change.
- CI and the release workflow install their modules through `tools/Install-BuildModule.ps1`, which tries again (up to four times, waiting longer each time) when the PowerShell Gallery answers 5xx - a 504 from the Gallery had failed a release.
- The release workflow publishes pre-releases: a `Prerelease` value in the manifest (`0.14.6-preview1`) is tagged `v0.14.6-preview1` and published as a pre-release; `tools/Step-ModuleVersion.ps1 -Prerelease` sets or clears it.

### Fixed

- Three test files (`GovernanceAssessment`, `PolicyRemediation`, `PSRule`) failed on GitHub Actions only: Spectre.Console's default enrichers detect CI and turn colours back on, so the captured console text held colour codes. Their captures now turn the enrichers off, as the others do.
- `Get-AACTerraformPlan` counted a pure import (or move) twice in its totals: once as its action, and again as an import (or move).

## v0.14.5

A Well-Architected assessment with a go-live gate, insights for Key Vault, storage accounts, Application Gateways and the hybrid network, a network topology diagram, workbook-style heat maps in every report, and clearer Entra ID group membership.

### New

- **Well-Architected assessment** across the five pillars, scored by pillar, design principle and check, from one Resource Graph batch:
  - `Invoke-AACWafAssessment`: Reliability, Security, Cost Optimization, Operational Excellence and Performance Efficiency. Scores are 0-100, with checks weighted by severity, each pillar's maturity, and heat maps by subscription, resource group or resource type. It checks about 60 catalogue items plus Advisor and Defender for Cloud, counting a finding once when Advisor or Defender repeat a catalogue check (`-KeepDuplicates` counts both). `-AttestationPath` scores the team's questionnaire answers, and `-HistoryPath` keeps the trend.
  - `Test-AACGoLiveReadiness`: a go-live gate. It checks pillar scores against `-MinimumScore` or `-PillarMinimum`, high-severity findings, `-RequiredCheck`, and principles covered. The verdict is Ready or Not ready, with the blockers listed. `-FailOnGap` fails a pipeline.
  - `Export-AACWafQuestionnaire`: one question per design principle (24), for what no API can test.
  - `Get-AACWafCheck`: the check catalogue, and how each principle is covered.
- `Get-AACKeyVaultInsight`: what Azure Monitor's Key Vault workbook shows (availability, transactions, latency, failures by status code, operations from the audit logs), plus:
  - saturation (`SaturationShoebox`);
  - posture: soft delete, purge protection, RBAC, network, private endpoints, Defender, audit logs;
  - callers denied or throttled, from both `AzureDiagnostics` and `AZKVAuditLogs`, with `-IncludeOperations`;
  - secrets, keys and certificates expired, expiring or never expiring (metadata only), with `-IncludeObjects`;
  - findings and a vault-by-signal heat map.
- `Show-AACApplicationGatewayMap`: Application Gateways as their connection flow, opened in your browser. It shows frontend IPs, listeners, rules, path rules and redirects, backend settings and probes, pools and targets (resolved to VMs and App Services), and WAF policies, inside their network and subnet.
  - **Health:** from metrics, or the live backend health check with `-IncludeHealth` (each target's state and the probe's reason).
  - **At the prompt:** the flows and findings: v1 SKU, WAF off or in Detection, old TLS policy, HTTP not redirected, certificates expired, expiring or uploaded, missing or mismatched probes, empty or unhealthy pools, and unused parts.
- `Get-AACNetworkHealth`: the Azure Network Monitoring workbook's signals with % of capacity, thresholds, findings and Resource Health, for:
  - ExpressRoute circuits: BGP and ARP availability per peering and link, link utilisation, traffic on one link, QoS drops, provisioning;
  - ExpressRoute gateways: CPU, packets per second, routes advertised and learned against their limits;
  - VPN and point-to-site gateways: bandwidth, BGP peers, point-to-site users, active-active;
  - connections and tunnels: connected or not, drops;
  - Azure Firewall: health, SNAT, throughput, latency;
  - NAT gateways: data path, drops, SNAT.

  Every finding says when it happened (the peak, the first and last time it was seen, or since when), and each report gives the period covered.
- `Invoke-AACStorageAccountAssessment`: what Azure Monitor's Storage accounts workbook shows - its Overview tab (transactions, end-to-end and server latency, errors by response type) and Capacity tab (used, blob, file, queue and table capacity, with blob, container and share counts) - plus:
  - health: availability, throttling, server, authorization and network errors, slow responses, time lost between client and service;
  - security: HTTPS, TLS, anonymous blob access, network access, shared keys and their age, key and SAS expiry policies, cross-tenant replication, blob logs, Defender for Storage;
  - data protection: redundancy, blob, container and file share soft delete, versioning;
  - cost: legacy account kinds, lifecycle rules, idle accounts, hot tier with little activity;
  - findings and an account-by-signal heat map; the reports' tabs follow the workbook.
- **Heat maps** in the console, PDF and HTML reports of any command (the report engine's new `HeatMaps`). The HTML is workbook style: a cell's colour is its score, and clicking it lists its findings.
- `Show-AACNetworkTopology`: the network topology of the tenant, management groups, subscriptions or regions, as an interactive diagram in your browser. Read-only, with Resource Graph.
  - **What it reads:** networks, subnets and peerings (across subscriptions, and to networks you can't see); VPN and ExpressRoute gateways, connections and circuits; Virtual WAN hubs; Azure Firewalls and network virtual appliances (VMs whose NIC forwards IP traffic); NSGs, route tables, NAT, Bastion, load balancers and Application Gateways; VMs, scale sets and private endpoints in their subnets, with the PaaS resources the endpoints serve. `-NetworkOnly` leaves out the workloads.
  - **Roles:** each network is a hub, a spoke of a hub, peered or standalone.
  - **Two layouts, switched on the page:** *Hub & spoke* puts each hub at the centre with its spokes in rings around it. *Hierarchy* nests boxes: tenant, management group, subscription, region, resource group, network, subnet (`-GroupBy` for fewer levels). Subnets are drawn in rows, sized by their prefix.
  - **Lines:** peerings with their state (red when not Connected), private endpoints to their PaaS, routes to the firewall or appliance that inspects them.
  - **Findings:** peerings not connected, routes to unknown next hops, spoke subnets whose internet traffic isn't inspected, peerings to networks you can't see, standalone networks.
- `Get-AACDiagnosticSetting -Status`: only the resources with these statuses (`Exported`, `Partial`, `Not to workspace`, `No setting`, `No logs`, `Unknown`). The view, objects, CSV, HTML and PDF, and the misconfigurations, then cover only those resources, while the coverage tiles still describe the whole scope. `-Status 'No setting'` lists the resources that support diagnostic logs but have no diagnostic setting at all.
- `Get-AACEntraGroupMembership` shows each group's **owners** (users and service principals, `Name (UPN)`), **when it was created** (UTC) and its **membership type** (Assigned, Dynamic, or Dynamic (paused)), next to its type and source. You'll find them in the console (groups table and each group's heading), on every row (`MembershipType`, `GroupCreated`, `GroupOwners`), in the HTML and PDF groups tables, and in the CSV, as three columns after Export-EntraGroupMemberShip.ps1's five (`Owners`, `CreatedDateTime`, `MembershipType`). Owners are read only for the groups asked for, not for the groups nested in them.
- `Get-AACEntraGroupMembership` reports are easier to read: each group is laid out the way admins read it, with its details first, then its direct members, then each nested group's members.
  - **Console:** each group has its own heading, then its details (type, source, membership type, created, owners, and counts with guests and disabled accounts), a **Direct members** table, and a **Nested group <path>** table for each nested group. A nested group in a table says its members are listed below, or that it's a loop already listed above.
  - **HTML:** the overview opens on a tree of the groups. Each group opens to its owners and direct members, and each nested group opens to its own members, with GUEST and DISABLED flags and search. A report of a few groups opens fully. New **Members** tab: everyone in each group once, marked Direct, Nested or Direct and nested, with the nested groups they come through. A "groups without owners" tile.
  - **PDF:** a page per group with its details, its direct members, and each nested group's members.

### Fixed

- `Show-AACResourceMap` drew false VNet peerings, with no state, between a hub's VPN gateway and its spokes. A spoke peering's `remoteGateways` and a gateway's `remoteVirtualNetworkPeerings` were read as peerings. Only a network's link to its remote network is a peering now.
- The map page (`Show-AACResourceMap`, `Show-AACNetworkTopology`) showed the hub-and-spoke layout buttons on every map: a CSS rule overrode their `hidden` attribute.
- `Get-AACEntraGroupMembership` left service principals out of every group, and so a nested group whose members were service principals looked empty, in the console view, the objects and every export. Microsoft Graph v1.0 leaves service principals out of `/groups/{id}/members` unless the request is an advanced query. The members are now read with `$count=true` and `ConsistencyLevel: eventual`, which returns them. Sign-in is unchanged: the `Connect-AAC` session.
- Nested group members are now shown expanded, not hidden under their group:
  - **CSV** (one row per group, Export-EntraGroupMemberShip.ps1's five columns): `Members` is everyone in the group, flattened. It holds the direct members and the members of every nested group at any depth, each once, with no `name (Group)` entries. `NestedGroupMembers` follows every depth and names each group by its path (`grp-a: x, y; grp-a > grp-b: z`), listing each group once.

## v0.14.3

A resource export admins can hand to anyone, Defender for Cloud alerts, eight commands for day-to-day operations and troubleshooting, faster HTML reports, and fixes to the alert queries and the HTML tiles.

### New

- `Export-AACResource`: every resource in the tenant, a management group, subscriptions, resource groups or resource types, to CSV, HTML and PDF. It gives more than Resource Graph Explorer's "Download as CSV":
  - **Where:** one Resource Graph query joins `resources` to `resourcecontainers` for the subscription name and state, the management group and its path up to the root, and the resource group's tags.
  - **Details:** the settings people look up for about 25 types, as one line. For example a VM's size, OS, image and power state; a storage account's TLS, public access and network rules; a NIC's IP, VM and NSG; an AKS cluster's version and nodes.
  - **Tags:** a dictionary on each object, and one `Tag: <key>` column per key in the CSV and the HTML report. Keys that differ only in case are treated as the same tag.
  - **Other columns:** parent, identity, provisioning state, public network access, created when Azure records it. `-Flatten` adds every property as a dotted column.
  - **Filters:** `-ResourceType`, `-ResourceGroupName`, `-Name`, `-Location`, `-Tag`, `-MissingTag` (for tag governance) and a KQL `-Filter` run in Resource Graph. Wildcards and `-Search` (text anywhere in the name, details, tags or ID) run afterwards.
  - **Speed:** subscriptions are split across up to four parallel queries.
- `Get-AACSecurityAlert`: Microsoft Defender for Cloud's security alerts, the equivalent of `Get-AzSecurityAlert` (Az.Security). It reads every subscription, or a management group's, in one Resource Graph query instead of one subscription and location at a time. Read-only; Reader or Security Reader is enough.
  - **Filters:** `-Status` (default Active and InProgress), `-Severity` and `-Days` are applied in the query. `-Name` (the alert's name or display name; on its own it reads every status, as `Get-AzSecurityAlert -Name` does), `-AlertType`, `-Tactic`, `-Incident`, `-ResourceGroupName` and `-ResourceId` take wildcards or match what's under a resource ID.
  - **Pipeline:** takes `ResourceId` or `Id` by property name, so resources from `Get-AACInventory`, `Get-AzResource` or `Get-AzVM` can be piped in.
  - **Each alert (`AAC.SecurityAlert`, a superset of the alerts in `Get-AACSecurityPosture`):** MITRE ATT&CK tactics and techniques, the resource's type and group (or the compromised entity), `Hosts`, `Accounts` and `IpAddresses` read from the alert's entities, extended properties as a dictionary, the description and remediation steps as plain text, age, incident, product, location, and `Occurrences` (how many alerts share its type and resource).
  - **Report:** tiles; charts by severity, MITRE tactic (in kill-chain order), resource, day and alert type; the alerts; and the recurring ones (three or more of a type on one resource), to fix at the source or tune with a suppression rule. Subscriptions with no Defender plan on are pointed out, because they raise no alerts. Console view, objects, CSV, HTML and PDF.

- **Eight commands for operations and troubleshooting** ([#8](https://github.com/ChendrayanV/Azure.Admin.Console/issues/8)). Like the rest, they take the usual scope and give a console view, objects, CSV, HTML and PDF. All are read-only in Azure.
  - `Get-AACResourceHealth`: each resource's Resource Health (Available, Unavailable, Degraded, Unknown), the reason and since when, worst and longest-down first. It adds the latest platform event in the window (a reboot, a live migration) and the Service Health events that hit the resource. `-IncludeHistory` reads Resource Health's history and works out the availability over `-Days` and how often the state changed. `-ServiceHealth` returns the outages, maintenance and advisories instead.
  - `Get-AACUnusedResource`: unattached disks, NICs and public IPs, NSGs and route tables on nothing, NAT gateways, load balancers and Application Gateways with no backends, empty App Service plans and SQL elastic pools, VMs stopped but still billed, deallocated VMs, old snapshots, unlinked private DNS zones, unused DDoS plans, WAF policies and IP groups, expired certificates and empty resource groups. Each is rated by what keeping it costs, with Billed and Since. `-IncludeCost` adds last month's cost.
  - `Get-AACResourceError`: failed operations from the Activity Log, one per correlation ID. Each is sorted into Authorization (the refused action and scope), Policy, Quota, Capacity, Throttling, Lock, Conflict, Validation or Not found, using the innermost error of a failed deployment, with the caller and the fix. Also grouped by error code. This answers the "failed actions and permission issues" part of the requested `Get-AACActivityLog`.
  - `Get-AACPrivateEndpoint`: every private endpoint connection with its state, target, IPs and names. It shows the DNS zone group, whether the endpoint's network (or one peered with it) is linked to that zone, and whether the zone is the right one for the service. It finds pending, rejected and disconnected connections, endpoints to deleted resources, targets still open to public networks and privatelink zones defined more than once.
  - `Get-AACLoadBalancerHealth`: load balancers (health probe status per backend IP and data path availability, from Azure Monitor), v2 Application Gateways (healthy and unhealthy hosts per pool) and Traffic Manager endpoints. It finds pools down, empty pools, rules without probes, single backends or instances, and the retired Basic load balancer and Application Gateway v1.
  - `Get-AACLegacyAuthentication`:
    - **Azure:** storage shared keys and other local or key authentication (Cosmos DB, Service Bus, Event Hubs, Event Grid, App Configuration, AI services and more), SQL and PostgreSQL passwords, the ACR admin user, Redis access keys and its non-TLS port, AKS local accounts or no Entra ID, Linux password login, App Service basic publishing credentials, TLS 1.0/1.1 and Key Vault access policies.
    - **Entra ID:** sign-ins over legacy protocols, successful (High) or failed (password spraying); whether Conditional Access or security defaults block legacy authentication; implicit grant and public client flows; client secrets; SMS and voice.
  - `Get-AACOrphanedIdentity`: role assignments to deleted principals, user-assigned identities attached to nothing and with no federated credential, managed identities whose resource is gone, the tenant's service principals not signed in for `-InactiveDays` (90), and app registrations with only expired credentials or no owners. Severity follows the access each still holds.
  - `Export-AACDiagnosticBundle`: a zip for a support case or a colleague. For each resource (`-ResourceId`, piped in, or `-ResourceGroupName`) it holds the configuration, Resource Health and its history, the Activity Log, diagnostic settings, locks, Advisor, Defender for Cloud, non-compliant policy states, alerts, recent changes and role assignments. A README, `summary.json` and `summary.html` sit on top. Keys, passwords, tokens, connection strings and SAS are redacted before anything is written. `-WhatIf` is supported; an existing zip is only replaced with `-Force`.
  - The rest of #8 maps to existing commands: `Get-AACAccessReview` (role assignments, service principal access), `Get-AACChangeHistory` (activity), `Get-AACFailoverReadiness` (backups) and `Get-AACDependencyGraph` (dependencies). The README has the mapping.

### Improved

- HTML reports are written about five times faster: 10,000 rows of 20 columns took 6.8 seconds and now take 1.4. Each cell used to be read through a helper function call. Every command's HTML report benefits.
- `Get-AACPropertyValue`, called for every value in cost rows, query pages and tokens, is a plain function now; an advanced function's parameter binding made each call about three times slower. The converters share one case-insensitive reader, `Get-AACMember`, which tries the exact key first, instead of eight copies that scanned every key.
- Module best practices (Azure PowerShell's module guidelines):
  - The manifest's description is short again and links to the documentation, and the tags cover the newer areas.
  - Every object type the newer commands return has a default display, so they show as a short table at the prompt.
- The demo (`Azure.Admin.Console.Demo`) runs every command, the new ones included, from the module's test fixtures. The test data of three commands moved into `Tests\Fixtures` so the demo can share it.

### Fixed

- The security alerts couldn't be read by `Get-AACSecurityPosture` or `Invoke-AACDefenderAssessment` (Resource Graph: "Query is invalid ... ParserFailure"). The alert queries named a column `time`, a KQL type keyword; it is now `generated`.
- HTML reports drew an empty tab bar, a band with a line, across the top of the tiles in every report without tabs: the bar's `display: flex` overrode its `hidden` attribute. Hidden elements are now always hidden.
- The console view stopped paging in hosts that replace `Console.Out` after start-up, such as VS Code's PowerShell extension. Paging is now skipped only when the output is redirected or captured.

## v0.14.2

The estate on one screen with `Show-AACDashboard`, ten commands for the questions cost, security, operations and compliance teams ask every day, and an access review that tells people and workloads apart.

### New

- **Ten commands for cost, security, operations, compliance and resilience** ([#10](https://github.com/ChendrayanV/Azure.Admin.Console/issues/10)). All are read-only, take the usual scope, and give a console view, objects, CSV, HTML and PDF. Each finding has a severity, impact, remediation and effort.
  - `Get-AACCostAnomaly`: spend spikes, drops, new spend, level shifts and steady rises per service, resource group, region or meter, found with robust statistics (a median/MAD baseline). Includes the resources behind the largest anomalies, a month-end forecast and how each subscription compares with the others. The issue's name, `Get-AACCostAnomalies`, was made singular because the build's analyzer rule rejects plural nouns.
  - `Get-AACAttackPath`: paths from the Internet (NSG rules evaluated in priority order, public apps, AKS API servers, open data stores) through managed identities to control or data access, with blast radius and risk. Defender for Cloud's own attack paths are added when Defender CSPM provides them.
  - `Get-AACAccessReview`: covers Azure RBAC (permanent, PIM-activated, eligible), classic admins, Entra ID roles and Microsoft Graph application permissions. It finds standing privileged access, guests, apps that can grant access or take over the tenant, disabled, dormant and deleted principals, unused write access (Activity Log), wildcard custom roles and too many Global Administrators. The attestation CSV has Decision and Reviewer columns. Every row has an Action - what to do, for the kind of principal. Just-in-time (PIM) is recommended only for users, guests and groups. Service principals and managed identities with elevated access are flagged as the risk they are, but PIM needs a person to activate a role: they are told how to narrow it (Role Based Access Control Administrator with a condition in place of Owner, resource groups in place of the subscription) and how to protect the credential, and access they haven't used is "Review usage" - check the sign-in logs first - not "Remove". Unused write access is judged only on what the Activity Log records, so roles with data-plane access (blobs, secrets, messages) are never called unused.
  - `Get-AACChangeHistory`: one entry per operation, with caller, client IP, correlation ID and status. It shows the before and after of each property (Resource Graph changes), how to undo it, its risk and origin (manual, automation, Azure), and the alerts and health events that followed.

- a subscription with no cost in the period is now a state of its own rather than an empty "(no currency)" section: its `Status` is `No cost`, it's left out of the charts and totals, and it's listed - a grey line at the console ("sub-dev: no cost since Apr 2026"), a tile and an info note in the HTML report, a "Subscriptions with no cost in this period" table in the PDF. The progress says how many ("5 read (1 with no cost)"). Subscriptions that couldn't be read are still listed as warnings with the reason.
- `Invoke-AACApplicationInsightQuery` reads every row in the period by default (up to the query API's limit of 500,000) instead of the newest 1,000; `-Top` still limits it. The views show every row, a page at a time - the exceptions view's list is no longer capped at 25, nor the table view at 200.

### Fixed

- `Show-AACCost -PdfPath` failed with "The property 'Count' cannot be found on this object" when a subscription had no costs at all. Such a subscription has no billing currency, so the PDF gave it a summary of its own - with no services or resource groups, which the top-services table didn't allow for.
- `Invoke-AACApplicationInsightQuery` failed with the same error when the query returned no rows (a quiet workspace, a short `-Last`, filters that match nothing). It now returns nothing and shows the empty view.
- `Get-AACFirewallRule -SourceAddress`, `-DestinationAddress` and `-Fqdn` missed a rule with exactly one address and exactly one IP Group address (or one destination and one target FQDN): the two were joined as one text (`10.0.0.110.1.0.0/16`) instead of a list of two.
- `Invoke-AACApplicationInsightQuery` queried through an Azure Resource Manager route that isn't registered: `-ApplicationInsightsName` failed with "No registered resource provider found for location ... and API version '2018-04-20' for type 'components/api'". It now uses each service's documented query API - `api.loganalytics.azure.com/v1/workspaces/{workspace ID}/query` and `api.applicationinsights.io/v1/apps/{app ID}/query` - with a token for that API taken from the `Connect-AAC` sign-in's refresh token (no second sign-in; kept per API until it nears expiry). A query error now shows the query API's own reason, innermost detail included ("Failed to resolve column ..."). An App Registration of your own (`Connect-AAC -ClientId`) needs the delegated Data.Read permission of both APIs.
- `Invoke-AACApplicationInsightQuery -LogWorkspaceName` returned "no exceptions" without saying why. A workspace only holds the exceptions of the Application Insights resources that send to it. When it has none, a warning now names those resources, or - if none send there - lists the ones you can see, where each sends its data, and the `-ApplicationInsightsName` command to query one directly. A reply from the query API without a result table is now an error instead of an empty result, and `-Verbose` shows the endpoint, timespan and KQL.
