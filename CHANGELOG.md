# Changelog

All notable changes to Azure.Admin.Console. Versions before 0.10.0 were never published to the PowerShell Gallery.

## Unreleased

### New

- `Invoke-AACM365Assessment` reports Microsoft 365 tenant discovery and security posture from the Microsoft Graph REST API, with no AzureAD, MSOnline, AzureADPreview or Microsoft.Graph modules. Every call uses the one Graph token of the `Connect-AAC` sign-in; about 25 calls run in parallel, each followed through its pages.
  - **Entra ID:**
    - tenant details and directory sync
    - licences and security defaults
    - user and guest settings, and cross-tenant access
    - Conditional Access policies and named locations
    - admin roles, active and eligible (PIM), with each admin's MFA registration
    - every user's MFA registration
    - authentication methods and identity providers
  - **Microsoft 365:**
    - domains
    - Microsoft Secure Score and its controls, with the gap and how to fix each
    - SharePoint and OneDrive sharing
    - audit logging: Purview audit log search, from its Secure Score control, and the Entra audit log
  - **Intune:**
    - tenant settings and enrollment restrictions
    - compliance policies
    - endpoint security policies: antivirus, firewall, disk encryption, EDR, attack surface reduction and account protection
    - managed devices: compliance, encryption, jailbreak, stale
    - Entra ID devices no MDM manages
  - **Zero-trust findings, each with what to do.** For example:
    - MFA not required of everyone or of admins
    - legacy authentication not blocked
    - no risk-based policy, or policies left in report-only
    - Global Administrator count and standing privileged access
    - admins and users without MFA registered
    - SMS and voice on, FIDO2 off
    - users able to register apps, invite guests or create tenants
    - Anyone links and guest resharing
    - audit log search off and a low Secure Score
    - devices with no compliance policy counted as compliant
    - non-compliant, stale, unencrypted and rooted devices
    - missing endpoint security policies
    - personal enrollment and active unmanaged devices
  - **Identity and application checks:**
    - **MFA coverage:** registered and phishing-resistant MFA for members, admins and guests, and the MFA policy's exclusions.
    - **Emergency access accounts:** found by being excluded from every enabled Conditional Access policy, or by name. Checked for two of them, Global Administrator, cloud-only, enabled, and a passkey.
    - **Dangling admins:** privileged roles held by deleted, disabled, guest, idle or on-premises-synced accounts, or by apps.
    - **Role overlap:** Global Administrator plus other roles, three or more privileged roles, and roles both active and eligible.
    - **Expiring and long-lived credentials:** secrets and certificates on app registrations and non-Microsoft enterprise apps.
    - **Over-privileged app permissions:** application permissions on Microsoft Graph and delegated consents, rated Critical (can take over the tenant), High (tenant-wide data) or Medium. Microsoft's apps are told apart from yours and third parties', and verified publishers from unverified ones.
    - **Dangling redirect URIs:** each host is looked up in DNS, so a deleted Azure host anyone could claim is flagged. Wildcard, non-HTTPS and localhost-on-multi-tenant URIs are flagged too.
    - **Legacy authentication:** the actual IMAP, POP, SMTP AUTH, ActiveSync and similar sign-ins in the last `-SignInDays`, read with one query per protocol.
    - **User consent:** who can consent to which apps, group owner consent and the admin consent workflow.
    - **Security defaults:** flagged when left on in a tenant licensed for Conditional Access.
    - **PIM role settings:** MFA, approval and justification on activation, maximum activation time, and permanent assignments, for every privileged role.
    - **Groups behind exclusions and roles:** who is actually in the groups excluded from Conditional Access and the groups holding admin roles, nested members included. Large or dynamic excluded groups and guests in role-holding groups are flagged.
    - **Access reviews:** whether admin roles and guests are reviewed.
    - **Directory sync settings:** password hash sync and accidental deletion prevention.
    - **Threat protection** (a new tab): risky users, Identity Protection risk detections and Microsoft Defender XDR incidents.
    - **Inactive licensed users:** no activity in 30 days, from the Microsoft 365 usage report.
    - **App protection (MAM):** iOS and Android policies for personal devices.
  - **A Coverage tab** replaces the Permissions tab. It lists every lens as *Assessed*, *Partly assessed*, *Not assessed* (with Graph's reason, the permission and any licence it needs) or *Not in this run*. It also lists what Microsoft Graph doesn't reach, each with what would cover it: Exchange Online, the unified audit log switch, Defender for Office 365, Purview, Teams, Defender for Cloud Apps, Sentinel and Entra Connect servers.

    Graph is read in batches, one after another, each with its own progress line: Entra ID tenant and policies; admin roles, MFA and users; sign-in and audit logs; applications; Microsoft 365; Intune; then the redirect URIs in DNS. Reads inside a batch run in parallel. The latest audit event and the latest Secure Score read one item, not every page of their history. Inside a batch, Microsoft Graph's app-role grants need its service principal first. Users are not all read: in a large tenant, every user with their last sign-in takes many minutes. Only the users the checks need are looked up: the principals of admin role assignments and the users Conditional Access excludes, by ID 15 at a time, plus break-glass-like names. If the last sign-in is refused, those lookups are read again without it.
  - **Permissions:** `-ListPermission` prints the read-only Graph permissions to sign in with, so one consent gives one token for everything. Graph reads it refuses are listed in a Permissions tab with the permission each needs, and the rest of the report is still made.
  - **Outputs:** a console view, an `AAC.M365Assessment` object, a CSV per table, and a tabbed HTML report (Overview, Findings, Entra ID, Microsoft 365, Intune, Permissions).

## v0.14.1

Microsoft Defender for Cloud assessed end to end, Azure Policy initiatives opened up to their member policies, and HTML reports that fit the screen - on a laptop or an external monitor.

### New

- `Invoke-AACDefenderAssessment` assesses Microsoft Defender for Cloud across subscriptions. It is read-only: Reader or Security Reader is enough, and it needs no Az modules. It reads Azure Resource Graph (`securityresources`), plus the Defender for Cloud REST API for the settings Resource Graph doesn't hold. Those are one call per subscription and setting, in parallel.
  - **Sections** (`-Section`):
    - Recommendations: every recommendation with its unhealthy, healthy and not applicable resources, the risk level, risk factors and attack paths (Defender CSPM), its control, description and remediation steps, and every unhealthy resource.
    - Attack paths: each path from entry point to target, step by step, with its risk factors, MITRE tactics and techniques, attack story and remediation.
    - Security alerts: alerts of the last `-AlertDays` (default 30), in every status, with MITRE tactics and techniques, compromised entity and remediation steps, plus the suppression rules.
    - Inventory: every resource Defender assesses, with the plan that covers it (on or off), its recommendations by severity, vulnerabilities, alerts and attack paths.
    - Vulnerabilities: sub-assessments, with CVEs and whether a patch exists.
    - Posture: secure score per subscription, the controls with their potential increase, plans with their sub-plan and extensions, multicloud and DevOps connectors, and just-in-time policies.
    - Regulatory compliance: standards, controls and the failed assessments.
    - Environment settings: security contacts, alert and attack path e-mails, and the Defender for Endpoint and Defender for Cloud Apps integrations.
  - **Findings, each with what to do:**
    - a plan off for resources the subscription has
    - Defender CSPM or Resource Manager off
    - Servers on Plan 1
    - no security contact, alert e-mails off or only for High alerts, owners not notified
    - the Defender for Endpoint integration off
    - a secure score under `-ScoreWarningPercent`
    - Critical and High attack paths
    - High alerts still active, and Medium alerts open for over a week
    - suppression rules with no expiry
    - just-in-time ports open to any source
  - **Outputs:** a console view, an `AAC.DefenderAssessment` object with every table, a CSV per table, and a tabbed HTML report in the portal's order.
- **HTML reports can have tabs.** A report that asks for them (`Write-AACHtmlReport -Tab`) gets an Overview tab, with the tiles, charts and tree, then a tab per section, each with a count badge.
  - The open tab is kept in the URL (`#tab=`).
  - A tile or chart that filters a table opens that table's tab.
  - Printing still shows every tab.
  - Other reports keep their layout.
  - A new `path` column type shows a chain of steps (`a → b → c`) as chips joined by arrows, and as a numbered list in the row details.

### Changed

- **HTML report tables fit the screen, on a laptop or an external monitor.** Every command's HTML report shares one page (`Private\DataReport.html`), so all of them have these changes.
  - **Each table scrolls in its own box,** sized to the window. Its header row and its horizontal scrollbar stay on screen, and its first column stays put when the table scrolls sideways. Before, the scrollbar was at the bottom of up to 200 rows, and the headers scrolled away with the rows.
  - **Width:** *Fit* (the whole window) or *Centered*.
  - **Rows:** *Compact* (one line per cell) or *Comfortable* (up to two).
  - **Sensible defaults:** until the viewer picks, a wide screen (1600px and over) gets Fit and a short one (900px and under) gets Compact. Each choice is remembered in the browser for every report.
  - **Readable text columns:** plain text columns are no longer squeezed to a word per line.
  - **Row details:** clicking a row opens all its fields in a panel on the right, in full, including the columns hidden from the table. Each field has a Copy button, and resources link to the portal. ↑ and ↓ move through the rows, and Esc closes the panel.
  - **Printing is unchanged:** every table at full width, with the full text.

- **Initiatives opened up: their member policies and the values their parameters end up with.** An initiative's parameters alone don't say what each of its policies does: a member policy's parameter can take an initiative parameter (which the assignment may set), a value fixed in the initiative, or the policy's own default. `Get-AACAssignedPolicy -ExpandPolicySet` returns one row per policy in force and parameter (`AAC.AssignedPolicyMember`). That covers every member policy of an assigned initiative, and every policy assigned on its own. Each row has the policy's effect, its default, what the initiative passes it (`InitiativeValue`, `InitiativeParameter`), the effective value and where it comes from (`ValueSource`: Assigned, Initiative default, Initiative, Policy default, Expression, Not set). The effect is resolved the same way, and an effect override on the assignment counts (`EffectSource` Override). The view then lists each initiative's policies under its assignment, `-CsvPath` writes these rows, and the HTML report always has the table (*Policies in force*). `Invoke-AACPolicyAssessment` opens up every assigned initiative too: each member policy with its effect, its parameter values and its compliance, including policies with no compliance data. They come back as the `InitiativePolicies` of each returned assignment, an `initiative-policies` CSV and an HTML table (*Policies in the initiatives*). Both commands resolve the values with one helper (`Resolve-AACPolicySetMember`).

### Fixed

- **Warnings were lost at an interactive terminal.** There, a command's work runs inside the live progress display, and PowerShell drops the warnings written inside it. So `-WarningVariable` and `-WarningAction` never saw messages such as "No group named 'grp-typo' was found", and the warnings that were printed broke the display. They are now kept and written once the display ends.
- **The view was paged even when it wasn't drawn to the terminal.** `Invoke-AACPagedOutput` paged whenever the PowerShell console was interactive, even when Spectre.Console was drawing somewhere else (a capture, as the tests use). That output went to the terminal instead of where it was being drawn. It now pages only when Spectre draws to the terminal.

## v0.14.0

Assessments: Azure Policy as a whole, AKS clusters through every lens, virtual networks, Log Analytics workspaces and the whole environment in the spirit of Azure Resource Inventory - plus diagnostic settings, Terraform plans, a storage account deployment, and sign-in without a browser (device code, service principals, managed identity).

### New

- `Invoke-AACPolicyAssessment` - Azure Policy assessed as a whole, following the analysis of AzPolicyLens (github.com/Azure/AzPolicyLens): Reader and Azure Resource Graph only, no Az modules. Discovery is tenant-wide: the management group hierarchy, every assignment, exemption, custom definition and initiative, and every role definition. The assigned built-in definitions and initiatives (and their member policies) are then read by ID, from Resource Manager when Resource Graph lacks them, along with the assignments' managed identities' role assignments. Compliance is counted as AzPolicyLens counts it: each resource once, at its worst state, and (compliant + exempt) / all. It is reported overall and by subscription, management group, assignment and subscription, policy and category, rated against `-ComplianceWarningPercent` (default 80). Findings with what to do: definitions assigned directly, DoNotEnforce, missing definitions, assignments and subscriptions under the threshold, deprecated or preview policies assigned, excluded scopes that don't exist, the same definition assigned twice on one scope path, Deny without a non-compliance message, DeployIfNotExists and Modify without a managed identity or missing the roles their policies list, exemptions expired, expiring (`-ExemptionWarningDays`, default 30), without expiry or for a deleted assignment, unassigned custom definitions and initiatives, unused policy definition groups, one control under different group names, and no category. Scope: everything, `-ManagementGroupId` (and everything under it) or `-SubscriptionId` (with every assignment that reaches them). `-Audience Platform|Application` follows AzPolicyLens's detailed and basic wikis. Outputs: a console view, `AAC.PolicyAssignmentReport` objects, a CSV per table, a PDF, and an interactive HTML report with the management group tree and each level's compliance.
- `Invoke-AACAksAssessment` - AKS clusters through every lens, read-only, no Az modules or kubectl: every setting that matters by area and every node pool; about 35 Well-Architected checks across the five pillars (Pass or Fail, a score per pillar, what to do) - SLA tier, zones, system pool, version support, local accounts, Entra ID and Azure RBAC, API server exposure, network policy, Azure Policy, Defender, workload identity, node images, upgrade channels, audit logs, autoscaler, ephemeral disks, kubenet, subnet IPs at full scale and more; PSRule for Azure's AKS rules (`-Baseline`, `-ExcludeRule`, `-SkipPSRule`); Azure Policy for Kubernetes consolidated by namespace, workload, policy and cluster as the AKS Policy Compliance Toolkit does - workloads inferred from pod names, effects resolved, system namespaces left out unless `-IncludeSystemNamespace`, Azure Policy's 500-record cap flagged - and, with `-IncludeConstraint`, Gatekeeper's complete counts through AKS run command; versions, support and upgrades, node images; Advisor and Defender. A console view, `AAC.AksCluster` objects, CSV files (with each namespace's non-compliant workloads), a PDF and an interactive HTML report.
- `Invoke-AACAssessment` - an Azure environment assessed end to end, in the spirit of Azure Resource Inventory (ARI), read-only and REST only (no Az modules, no Excel). Scope: the tenant (`-TenantId`, its ID or a domain, signs in to it when the session is for another), `-ManagementGroupId` (at any depth), `-SubscriptionId`, `-ResourceGroupName`, `-TagKey`/`-TagValue`, `-Category`. A sheet per resource type present - about 95 types in 14 categories, from VMs (with their NIC's IP, network and NSG, the size's vCPUs and memory), scale sets, disks, AKS and node pools, containers and databases to virtual networks, subnets (free IPs), peerings, NSG rules, firewalls, gateways, private endpoints, App Services, backup items and AI services - as Resource Graph projections; each row also carries its Advisor retirement notice and recommendation count, its cost (`-IncludeCost`) and tags (`-IncludeTag`). Overview sheets (subscriptions with their management groups, resource groups, resource types, every resource), Advisor recommendations and score, retirements, Defender for Cloud (`-SecurityCenter`), Azure Policy compliance, outages (Resource Health), compute quotas (`-QuotaUsage`), support tickets and reservation recommendations. Reports (`-Output`): a CSV per sheet, an interactive HTML report (tiles, charts, the tenant tree, a table per sheet by category with contents), a bookmarked PDF, and interactive network, organization and resources diagrams (`-DiagramFullEnvironment` draws every resource). A live Spectre.Console progress display per phase, and a summary of what was found, what needs attention and where the reports are. `-Automation` runs in an Azure Automation runbook (managed identity sign-in, plain progress lines) and `-StorageAccount`/`-StorageContainer` uploads the reports to blob storage.
- `Connect-AAC` signs in without a browser on this machine: `-DeviceCode` (a code entered at microsoft.com/devicelogin), a service principal with `-ClientSecret`, `-CertificatePath` (a .pfx) or `-CertificateThumbprint` (the certificate store) - the token request signed with the key, never sent - and `-Identity` for a managed identity (Azure Automation, a VM, App Service, Functions). App-only sessions get a new token when one runs out, for Azure Resource Manager and any other API (Azure Storage for the upload).
- `Invoke-AACVirtualNetworkAssessment` - virtual networks assessed from Azure Resource Graph, read-only: every network you can see, or by subscription, management group, resource group and name (wildcards). Per network: role (hub, spoke), address space with total, in-subnet, unallocated, usable, used and available IPs, the free CIDR blocks a new subnet can take, overlaps with any other network, DNS servers and linked private DNS zones, DNS resolvers, DDoS, encryption, flow logs, gateways, firewalls and Bastion. Per subnet: usable / used / available IPs, purpose, NSG, route table and default route, NAT gateway, the outbound path (NAT gateway, firewall, forced tunnelling, public IPs, private subnet, default outbound access), service endpoints, delegations, private endpoints and their policies, NICs and VMs. Peerings with state, sync, flags, remote space and reverse peering; private endpoints with their connection and DNS zone; ASGs with their members and the NSG rules naming them; and the NSGs on the subnets assessed as `Get-AACNetworkSecurityGroup` does. Findings by severity with what to do - full subnets, peerings down or out of sync, special subnets too small, an NSG or default route on GatewaySubnet, subnets without NSGs, public-IP VMs, default outbound access, no DDoS, no flow logs, unlinked privatelink zones, Basic or non-zonal gateways, overlaps and more. A console view, `AAC.VirtualNetwork` objects (with their subnets, peerings, free ranges and findings), and CSV, PDF and interactive HTML reports.
- `Deploy-AACStorageAccount` - creates or updates a storage account and what's in it (containers, file shares, queues, tables, lifecycle rules, private endpoints with a private DNS zone group, diagnostic settings, role assignments, a lock, blobs) idempotently with the Azure REST APIs - no ARM, Bicep or Terraform template. The Azure Verified Module's parameter names and defaults (enforced on every run, as Bicep would); a `.psd1`, a `.json` or an AVM parameters file, and parameters. **Plan**: read and compared property by property - Create, Update, No change, Replace (can't change in place: location, kind, hierarchical namespace, infrastructure encryption, zonal or Premium redundancy), Drift (`-Prune` deletes). **Gates**: the name, the policy assignments for storage, Azure Policy's verdict on every write's exact body (`checkPolicyRestrictions`: Deny blocks, Audit reported, Modify and Append shown), PSRule for Azure on the account as it will be. **Apply**: dependency order, PUT to create, PATCH with only what changed, long-running operations followed, role assignments named from scope, principal and role, blobs only when their MD5 differs. **Verify**: read again - no changes. A failing PSRule rule blocks the deployment and comes with its fix - the setting and value (`Get-AACStorageRuleFix`), or what to do when no setting can fix it; the view gathers the settings into a configuration snippet, and `-UseSuggestedFix` deploys with them after checking every gate again (tested against the real PSRule for Azure rules: every automatic fix makes its rule pass). `-WhatIf`, `-Force`, `-FailOn Audit`/`Drift`, `-ExcludeRule`, `-PlanPath`. The module's first command that writes: the HTTP layer gained PUT, PATCH, HEAD and response headers (`Invoke-AACArmWrite`), and the PSRule engine can run on objects given to it.
- `Get-AACDiagnosticSetting` - every resource's diagnostic settings, flattened, and the resources whose logs don't reach a Log Analytics workspace. Lists the resources with one KQL query (Resource Graph), adds each storage account's blob, file, queue and table services and each subscription's activity log, reads which types have log categories once per type and kind (`diagnosticSettingsCategories`), then each resource's settings (`diagnosticSettings`, 2021-05-01-preview) in parallel. Each resource gets a status - Exported, Partial, Not to workspace, No setting, Unknown - with the reason, counting a category reached by name or through `allLogs` / `audit`. Misconfigurations by severity: no setting, activity log not exported, no workspace destination, a deleted workspace, missing categories, nothing enabled, logs sent to a workspace twice, a workspace other than `-ExpectedWorkspace`, another region, the retired retention policy. `-NotExportedOnly`, `-ExpandSetting` (one row per setting), `-IncludeUnsupported`, `-ResourceType` (wildcards). Console view, objects, CSV, HTML and PDF.
- `Invoke-AACLogAnalyticsWorkspaceAssessment -WorkspaceId` - one Log Analytics workspace assessed, read-only, by workspace ID (GUID), resource ID or name: billable and not billable tables with their size over `-Days` (billable and free GB, share, daily average, last record) merged with each table's plan and retention; every workspace setting (anything not mapped goes under Other); recommendations from Azure Advisor and the assessment's own rules (pricing and commitment tiers, the daily cap, spikes, retention, Basic/Auxiliary plan candidates, ContainerLog, AzureDiagnostics, unused custom tables, retired MMA agents, silent agents, operation errors, unassociated DCRs, shared keys, network access, access control mode, query auditing, diagnostic settings); the data collection rules sending to it with their associations; and the Workspace Insights views - Overview, Usage (per day, solution, resource, computer), Health (`_LogOperation`, latency), Agents, Query Audit (`LAQueryLogs`), Data Collection Rules and Change Log (activity log). KQL runs up to 5 queries at a time, each on its own, so one failing doesn't stop the rest. `-Section` reads only what is asked for. Console view, an `AAC.LogAnalyticsWorkspaceAssessment` object, CSV (the tables) and HTML (every section).
- `Get-AACTerraformPlan` - a Terraform plan in JSON (`terraform show -json tfplan > plan.json`), read whole and flattened: one row per resource change (`AAC.TerraformChange`) with the action (Create, Update, Replace, Delete, Read, Import, Move, Forget), why, the Azure name, resource group, location and ID, and the attributes that force a replacement; `-ExpandAttribute` for one row per changed attribute (`AAC.TerraformAttributeChange`) with its before and after value, flattened to a path (`tags["cost.centre"]`, `security_rule[name=ssh].access`, `policy_rule{json}.then.effect` inside a JSON-encoded string). Blocks in a list are paired by content, then by name, then in order; a list in another order is reported as reordered. Outputs and the changes made outside Terraform (`resource_drift`, `-IncludeDrift`) are read too. Sensitive values, which the plan JSON holds in clear text, are never shown, returned or written. Offline: no sign-in. `-Action`, `-Address`, `-ResourceType` (wildcards); a binary plan, Terraform state or other JSON is refused with what to run; UTF-16 files are read. Console view (Terraform's summary line, a table per action with `+`, `-`, `~` attribute lines and `# forces replacement`), objects, CSV and HTML.

### Changed

- **HTML reports can group their tables.** A table with a section is drawn under its heading, and the sections are listed in a Contents block above the tables - for reports with many tables, such as `Invoke-AACAssessment`'s.
- **The resource map draws management groups** as boxes, for the assessment's organization diagram.
- **Collapsible tables in every HTML report.** Each table now starts collapsed, with a header showing its title, row count and note; click it (or press Enter or Space) to show or hide the table, or use *Expand all tables* / *Collapse all tables*. A tile, chart bar or tree link that filters a table opens it first. Printing shows every table. One change to the shared page (`Private\DataReport.html`), so every command's report has it.
- **Bookmarks in every PDF report.** A PDF can't hide tables in most viewers, so each report now opens with its bookmarks panel showing: one bookmark per section and table, nested by level and collapsed. Where a report skipped a heading level, the bookmark tree used to get untitled entries; they are gone (`Set-AACPdfOutline`).

### Fixed

- **`-WhatIf` and hashtables.** Under `-WhatIf`, `ForEach-Object <Name>` on a hashtable treats reading the key as an operation and returns nothing - silently. Commands that run under `-WhatIf` turn it off while they only read, and the new code reads keys with script blocks. A module test also catches any variable that is a parameter under another case (`$current` and `-Current` are one variable).
- **Resource Graph errors said only "Please provide below info when asking for support".** The real reason (an invalid query, and where) is in the error's `details`, which weren't read. Every command now shows it, with the support line (timestamp, correlation ID) at the end.
- **The live progress display hid a command's own variables.** Its script block runs inside `Invoke-AACProgress`, whose locals (`$action`, `$description`, `$progress`...) shadowed any caller variable of the same name: `Get-AACTerraformPlan -Action` read the display's callback instead, so at a terminal it filtered out every change. The helper's locals are now prefixed `aac`.
- **Objects lost their format view after the console view.** `Select-Object -First` adds a `Selected.` type name to the very objects it passes on, so rows shown in a view and then returned with `-PassThru` lost their `AAC.*` type. The new commands' views use `Select-AACFirst`, which passes them on untouched.

## v0.13.0

Azure Policy - what is assigned and how compliant it is - blob storage sized by container, which VM sizes you can use, a detailed network security group assessment, what everything costs in the tenant inventory, and faster reads throughout: Azure calls share one pooled HTTPS connection, and independent queries run in parallel.

### Fixed

- **Piping to `Select-Object -First`** (for example `Get-AACSkuAvailability -Location uksouth | Select-Object -First 5`) failed with "The pipeline has been stopped." and an error panel, in every command: each command's error handler took PowerShell's stop signal for a failure. A stopped pipeline now just ends the command, and the rest of the script carries on; Ctrl+C still stops everything.
- `Invoke-AACPSRule` took minutes to read the settings of API Management services (and other resources with many child settings): each API, operation and policy was read with its own Azure Resource Manager call, one at a time - about 700 calls for 40 APIs of 15 operations. The reads now run in parallel, 12 at a time over one pooled HTTPS connection (`Invoke-AACArmParallel`), a level of children at a time across every resource: first each service's APIs, products and settings, then each API's operations and policies, then each operation's policy. The data PSRule checks is the same, in the same order. Throttling (429) and server errors are retried as `Retry-After` asks, dropped connections after a second or two, and the progress line counts the calls. In a test with 120 reads of 250 ms each: 30.5 seconds one at a time, 4.7 seconds in parallel.

### Nothing cut off

- **`Invoke-AACPSRule`'s view** listed only the first 3 resources of each failing rule and cut every reason at 110 characters. It now lists every resource - up to 50 per rule, then how many more and where to find them - with its whole reason, wrapped.
- **Objects at the prompt** (`-PassThru`, `-NoDisplay`): PowerShell's default tables cut long text with '...'. A format file (`Azure.Admin.Console.Format.ps1xml`) gives PSRule results, Advisor recommendations, Application Insights exceptions, inventory items (indented by depth, with secure score and cost), NSGs and NSG findings a few columns with long text wrapped.
- **Other views:** `Get-AACNetworkSecurityGroup` lists every High and Medium finding (was the first 25), `Get-AACInventory` every High-severity finding (was 10); `Invoke-AACApplicationInsightQuery` and query results wrap messages, types, operations and stack frames instead of cutting them at 50-140 characters (only values over 600 characters are shortened).

### Faster

- **One pooled HTTPS connection.** Every Azure Resource Manager, Resource Graph and Cost Management call now goes through one shared `HttpClient`, so connections are reused instead of a new TLS handshake per call. Throttling (429) and server errors are retried the same way everywhere, for as long as Azure's retry headers ask - `Retry-After`, Cost Management's `x-ms-ratelimit-...-retry-after` and Resource Graph's `x-ms-user-quota-resets-after` - and errors carry Azure's own message.
- **Resource Graph queries in parallel.** Commands that need several independent queries now send them together, up to 4 at a time (Resource Graph allows about 15 per 5 seconds), so a read takes about as long as the slowest query: `Get-AACInventory` (up to 8 queries), `Get-AACNetworkSecurityGroup` (5), `Get-AACFirewallRule` (4), `Get-AACAdvisorRecommendation` (3), `Show-AACResource` (3-4) and `Show-AACResourceMap` (its scope and resources together, and the resources outside the selection in parallel batches of 200).
- **`Get-AACNetworkSecurityGroup`** reads the NSGs' diagnostic settings 12 at a time instead of one after another.
- **`Show-AACCost`** reads its subscriptions 3 at a time instead of one after another (Cost Management allows only a few queries a minute).

### New

- `Get-AACAssignedPolicy` - every Azure Policy assignment and its parameters, one row per assignment and parameter (`AAC.AssignedPolicy`): the default, assigned and effective value, where the value comes from, allowed values, the scope (inherited from a management group or not), enforcement, policy or initiative, built-in or custom, category - and `ResourceType`, the resource types the policy targets, read from its rule's type conditions with parameters resolved (for an initiative, from the member policies that use each parameter).
  - **Fast:** the assignments, the definitions and initiatives they assign, and the initiatives' members come from Azure Resource Graph in a few queries, not one call per assignment; a definition it doesn't return is read from Resource Manager.
  - **Scope:** `-SubscriptionId` or `-ManagementGroupId` list what applies there, including assignments inherited from the management groups above; `-AssignmentName` filters by name or display name (wildcards).
  - **Output:** a console view (assignments by scope, resource types, each assignment's parameters as a tree), objects, `-CsvPath` and `-HtmlPath`.
- `Get-AACStorageAccountContainerSize` - how much is stored in every blob container of your storage accounts. Storage accounts from Azure Resource Graph, containers from Azure Resource Manager (Reader is enough), blobs from the blob service.
  - **Per container** (`AAC.StorageContainerSize`): blobs, size and size per access tier (Hot, Cool, Cold, Archive, no tier), snapshots, previous versions and soft-deleted blobs with their sizes (`-IncludeSnapshot`, `-IncludeVersion`, `-IncludeDeleted`), Data Lake directories, the newest change, public access, the `-Top` largest blobs, and - with `-IncludeBlob` - every blob (`AzureAdminConsole.StorageBlob`).

The parser reads each response body itself: PowerShell hands the arguments of every .NET method it calls to AMSI, and passing a 2 MB page as a string cost more than parsing it. Throttling is retried as Azure Storage asks.

Read-only, over REST (Reader, nothing deployed): `Microsoft.Compute/skus` (offered zones, the subscription's region and zone restrictions, capabilities), the vCPU usage (family and regional quota), the subscription's zone mapping (logical to physical), and with `-ClusterName` the AKS cluster and its node pools (Resource Graph).

  - **Output:** a console view (zones, quota, node pools, sizes usable first), `AAC.SkuAvailability` objects, `-CsvPath`, `-HtmlPath` and `-PdfPath`. Other services will follow.
- `Get-AACPolicyState` - Azure Policy compliance for every resource, from one Azure Resource Graph KQL query (`policyresources`) with the policies' and initiatives' display names; the assignments' names, scopes and enforcement read tenant-wide.
  - **Scope:** `-ManagementGroupId`, `-SubscriptionId`, `-ResourceGroupName` (each taking several values); `-ComplianceState` filters in the query.
  - **Flattened:** one row per resource and policy (`AAC.PolicyState`) - state, resource, type, resource group, subscription, location, policy, initiative, assignment, where it is assigned (by name), enforcement, effect, when it was evaluated.
  - **Compliance** as the Azure portal counts it, per resource, assignment, subscription, resource group and policy: a resource takes the state that ranks first across its policies (Non-compliant, Compliant, Error, Conflicting, Protected, Exempt, Unknown), and compliance (%) is (compliant + exempt + unknown + protected resources) / every resource evaluated; *Not started* states aren't counted.
  - **Output:** a console view (tiles, compliance by subscription and resource group, assignments least compliant first, every non-compliant resource by policy), the rows as objects, `-CsvPath`, `-HtmlPath` (a donut of the states, charts and tables of resources, states, assignments, policies, subscriptions and resource groups) and `-PdfPath`.
  - **The portal's tiles:** resource compliance with "313 of 2,560", non-compliant initiatives and non-compliant policies, each out of all (a policy is a definition, an initiative a set definition).
  - **Every state, however many.** The query keeps Resource Graph's `id` column, which Resource Graph needs before it returns a next page, so a large tenant's states no longer stop at the first page. Display names are joined on the definitions' full IDs. Resource Graph reads now ask for pages of 1,000 rows, and warn if a result comes back truncated without a next page.
  - `Get-AACSecurityPosture -Section Policy` now reads the same query and rolls it up with the same code - one implementation, so both commands show the same numbers as the portal. Previously the posture counted a resource once per policy, left exempt resources out, and showed each assignment against its subscription rather than where it is assigned; it now shows "Assigned at" (management group, subscription or resource group).
- `Get-AACSecurityPosture` - Microsoft Defender for Cloud and Azure Policy in one report, read with Azure Resource Graph (every query at once): `-Section Score, Recommendations, Alerts, Plans, Compliance, Policy`.
  - **Secure score:** each subscription's (Defender's points, added up as Defender does) and the controls with the potential increase of fixing each.
  - **Recommendations:** every unhealthy one per resource, with the secure score control it belongs to, description, remediation steps and its portal page.
  - **Alerts:** active and in-progress, with severity, intent, resource, age and the alert's page. **Plans:** which Defender plans are on or off - and a note when none is, so an empty alert list isn't mistaken for a clean one.
  - **Regulatory compliance:** each standard's passed and failed controls; a failed control traced to the resources failing the recommendations behind it. `-Standard` picks standards by name or wildcard.
  - **Azure Policy:** compliance per assignment (display names read tenant-wide, so management group assignments are named), and every non-compliant resource with the policy and its effect.
  - **One list of findings** (`AAC.SecurityFinding`) across the sections, most severe first; `-ResourceGroupName` and `-Tag` (exact values) narrow it to those resources.
  - **Output:** a console view, the findings as objects, `-CsvPath`, `-HtmlPath` (tiles and charts that filter tables of findings, subscriptions, secure score controls, compliance standards and controls, policy assignments and plans, with portal links) and `-PdfPath`.
- `Get-AACInventory -Insight` - what the estate is made of and what needs attention, in the same parallel Resource Graph read (11 more queries):
  - **Mix:** VM sizes, operating systems (from the VM's instance view, or its image), VM power states, Azure VMs and Azure Arc servers, storage account replication, database tiers (Azure SQL DTU / vCore / serverless, Cosmos DB provisioned or serverless, PostgreSQL, MySQL), tag coverage (the tags `Get-AACTagDefault` requires, or else the most used).
  - **Needs attention** (`AAC.InventoryFinding`): unattached disks, unused public IPs and NICs, VMs stopped but still billed, disconnected Arc servers, classic resources (retired), subnets 80% full or more, VPN and ExpressRoute connections down, empty resource groups - each with its cost this month with `-Cost`.
  - **Network:** every subnet's used and usable IPs (Azure keeps 5), and the VPN and ExpressRoute connections.
  - **Where it shows:** proportion charts and a table at the console; donut charts (a new chart type in the HTML reports, plain SVG) that filter a machines table, and tables of what needs attention, subnets and connections in HTML; a page in the PDF.
- `Get-AACNetworkSecurityGroup` counts the VMs each NSG protects - through their NIC or their subnet (`VirtualMachines`) - with a "VMs protected per NSG" chart at the console and in HTML, to see how standard the perimeter is.
- `Get-AACInventory`'s security recommendations have their description and remediation link (a portal link in the HTML report). Its Defender queries and objects are now shared with `Get-AACSecurityPosture` - one implementation.
- `Get-AACEntraGroupMembership` - who is in your Entra ID groups, read from Microsoft Graph: the groups by exact name (`-GroupName`, alias `-GroupNames`), by the start of their name (`-GroupNameStartsWith`), or every group; their direct members and everyone in the groups nested in them, followed to the end (a loop is listed once, not followed again).
  - **Flattened:** one row per group and member (`AAC.EntraGroupMember`) - group type (Microsoft 365, Security, Mail-enabled security, Distribution; dynamic, role-assignable) and source (cloud or synced from on-premises AD); member name, type (user, group, device, service principal, contact), user principal name, mail, member or guest, enabled or disabled, job title, department; Direct, Nested (with the path of nested groups and the depth) or Empty.
  - **Output:** a console view (tiles, a table of groups with their direct members, nested groups and unique users, guests and disabled accounts, and each group's members as a tree), the rows as objects, `-CsvPath` (alias `-OutputPath`), `-HtmlPath` (tiles and charts that filter a groups table and a memberships table, each downloadable as CSV) and `-PdfPath` (summary, groups, and each group's members).

A Microsoft Graph token is taken from it silently, as for Application Insights; the account needs to be allowed to read groups in Entra ID (tenant members are by default). With your own App Registration (`Connect-AAC -ClientId`), give it Microsoft Graph's delegated Group.Read.All and User.Read.All.
  - **Fast:** reads run 8 at a time over the pooled connection, a level of nesting at a time, each group read once; members are paged (999 a page) and throttling waits as Graph's `Retry-After` asks. A group whose members can't be read is reported with the reason, and the rest carry on.
- `AAC.Resource.Naming` - a PSRule rule that checks the names of resource groups and about 30 common resource types against Microsoft's Cloud Adoption Framework abbreviations (`rg-`, `vnet-`, `nsg-`, `kv-`, `st` + 3-22 lowercase letters and digits, ...). It runs without any setting; `AAC_NAMING_PATTERNS` replaces or adds patterns per type (`''` turns a type off) and `AAC_NAMING_IGNORE` adds names never checked. Names Azure creates and manages (AKS node resource groups, `NetworkWatcherRG`, `DefaultResourceGroup-*`, ...) are skipped. The defaults are one table in `PSRule\Rules\AAC.Naming.Rule.ps1`.
- `Invoke-AACPSRule` reads only what the rules need. With only the module's `AAC.*` rules, it reads names, types and tags from Resource Graph and none of the child settings PSRule for Azure's rules need (one to hundreds of calls per resource); `-NoExpand` does the same for your own rules. `AAC.Resource.Naming` on its own reads only the types it checks. `-ResourceType` now filters in the Resource Graph query itself.
- The module's tag rules read their tags from `Get-AACTagDefault` in `PSRule\Rules\AAC.Tags.Rule.ps1` (empty as shipped) when `-Configuration` names none, so an organisation's tags can be set once. A tag rule asked for with no tags to check is reported ("checked nothing: no tags are named", with how to name them) in the view, the HTML report and as a warning, instead of silently returning nothing.
- `AAC.Resource.Naming`'s reason is shorter and names the type as the table spells it: "The name doesn't match '^rg-', the naming convention for Microsoft.Resources/resourceGroups."
- `Invoke-AACPSRule -Rule` refuses a file path (use `-RulePath`) and an `AAC.*` name the module doesn't have, naming its rules; a `-Rule` that matches no rule is an error instead of an empty result.
- `Get-AACInventory -Cost` - what everything costs, from Azure Cost Management (Cost Management Reader, or Reader, on the subscriptions): the actual cost month to date and last month of every resource, rolled up to its resource group, subscription, management groups and the tenant.
  - **As few queries as possible:** one query for the whole tenant root group (or `-ManagementGroupId`) when the billing account allows it - Enterprise Agreement and Microsoft Customer Agreement - and otherwise one per subscription, 3 at a time. With `-SubscriptionId` or `-ResourceGroupName`, each subscription is asked directly.
  - **Every charge placed:** a child resource's cost (a database billed under its server's path, say) goes to the closest resource above it in the inventory; costs of deleted resources, and charges not tied to a resource, show under their subscription as **Deleted resources**.
  - **Never converted:** amounts stay in each subscription's billing currency; a level whose subscriptions are billed in different currencies says so instead of adding them up. A subscription whose cost can't be read says why (`CostStatus`); a subscription with nothing charged says 'No cost'.
  - **Where it shows:** the console (cost tiles, each node's cost month to date and last month, the top spenders), HTML (cost tiles, top-spend charts by resource, subscription and resource group, cost pills in the tree, and money columns totalled per currency), PDF (a cost section: totals, subscriptions, top resource groups and resources, deleted resources) and the objects (`CostMonthToDate`, `CostLastMonth`, `Currency`, `CostStatus`, and a `DeletedResources` item per subscription with such costs).
- `Get-AACNetworkSecurityGroup` - a detailed assessment of network security groups, read with Azure Resource Graph (NSGs, NICs, subnets, Network Watcher flow logs) and Azure Resource Manager (diagnostic settings, one call per NSG; `-NoDiagnosticSetting` skips them). Without parameters it assesses every NSG the account can see; `-SubscriptionId`, `-ResourceGroupName` and `-Name` (wildcards allowed) narrow it, each taking several values.
  - **Metadata and associations:** name, resource ID, subscription, resource group, location, tags; the subnets (VNet, prefix) and network interfaces (VM, private IP) each NSG is applied to.
  - **Rules:** every rule, custom and default, in the order Azure evaluates them - priority, direction, protocol, source, source port, destination, destination port (application security groups by name), action.
  - **Telemetry:** diagnostic settings (enabled or not; Log Analytics workspace, storage account, event hub; log categories) and flow logs - an NSG flow log, or a virtual network flow log on the NSG's VNet, subnet or NIC - with retention and Traffic Analytics.
  - **Findings**, each with a severity, the rule and what to do. High: an inbound Allow from `*`, `Internet` or `0.0.0.0/0` to every port or a management or database port (SSH, RDP, WinRM, SMB, Telnet, FTP, SQL, MySQL, PostgreSQL, Oracle, MongoDB, Redis, VNC, Docker, ...). Medium: a wide port range open to the internet; an NSG on no subnet and no NIC; a NIC NSG and its subnet's NSG that disagree (both evaluated, first matching rule by priority, as Azure does - so the traffic is blocked); no or a disabled flow log. Low: ICMP from the internet; everything allowed from the virtual network; a shadowed rule that never applies; flow logs kept under 90 days; no diagnostic settings. Info: flow logs without Traffic Analytics; only an NSG flow log (retiring on 30 September 2027); over 800 of the 1,000 rules an NSG can hold.
  - **Output:** a Spectre.Console view (tiles, the NSGs by risk, the High and Medium findings, and up to three NSGs in detail with their rules), `AAC.NetworkSecurityGroup` objects with their rules, findings, associations and logging, `-CsvPath` (every rule with its risk and finding), `-HtmlPath` (tiles, charts, and tables of NSGs, findings, rules, associations and logging, each with a CSV download) and `-PdfPath` (summary, findings, and a page per NSG with its associations, telemetry and rules).

## v0.12.0

Two new commands - a tenant inventory with Microsoft Defender for Cloud security posture, and an interactive resource map - plus fixes for two errors users reported (`Show-AACCost -PdfPath` and `Invoke-AACApplicationInsightQuery`), and errors shown as Spectre.Console panels. v0.11.1 was prepared but never published; its fixes are in this release.

### Highlights

- **`Get-AACInventory`:** the tenant as a tree - management groups > subscriptions > resource groups > resources - with counts and the Defender for Cloud secure score and findings by severity, in colour, on every node. A console tree, objects, and CSV, PDF and interactive HTML reports.
- **`Show-AACResourceMap`:** a map of one or more resource groups, opened in your browser - Azure icons, subnet placement, network paths, NSGs and route tables with their rules and risks - saved as PNG or JPEG.
- **Fixed:** `Show-AACCost -PdfPath` failed ("The property 'Count' cannot be found") when a subscription had no costs; `Invoke-AACApplicationInsightQuery` failed with the same error on an empty result, and with "No registered resource provider found" for `-ApplicationInsightsName`.

### New

- `Get-AACInventory` - the tenant as a tree, read with Azure Resource Graph: management groups (nested as in Azure) > subscriptions > resource groups > resources, with the subscriptions, resource groups and resources below every node and each resource group's most common types. Management groups with no subscriptions in the result are left out unless asked for; a subscription whose management group can't be read is shown under the tenant; empty resource groups are flagged. `-ManagementGroupId`, `-SubscriptionId` and `-ResourceGroupName` (each taking several values) set the scope; `-Depth` how deep the console tree goes. A Spectre.Console tree (in ASCII on consoles that aren't UTF-8), `AAC.InventoryItem` objects, `-CsvPath` (every node), `-HtmlPath` (tiles, charts, the hierarchy as a collapsible, searchable tree whose nodes filter the tables, and tables of management groups, subscriptions, resource groups and resources, each with a CSV download) and `-PdfPath` (summary, hierarchy, subscriptions, resource groups, resources by type, resources).
- `Get-AACInventory` shows the security posture from Microsoft Defender for Cloud (Resource Graph `securityresources`; Reader is enough):
  - **Secure scores:** each subscription's secure score (Defender's own), added up for management groups and the tenant as Defender does. Each resource's and resource group's score is the share of its assessed recommendations that are healthy.
  - **Colours:** Good (70%+) green, Fair (40-69%) amber, Poor red, with unhealthy findings counted by severity (High red, Medium amber, Low blue) on every node.
  - **Controls and recommendations:** the security controls with the potential score increase of fixing each (their impact), and every unhealthy recommendation with severity, user impact, effort and category.
  - **Where it shows:** the console (tiles, the tree, the controls with the most to gain, the High findings), HTML (tiles, charts, pills in the tree, score columns, controls and recommendations tables) and PDF (coloured scores in the hierarchy, a security section). Objects carry `SecureScore`, `Rating`, `Severity`, `High`, `Medium`, `Low`, `Findings` and `TopFindings`.
  - **Skipping it:** `-NoSecurity`; without Defender data the inventory says so and shows no security columns.
- the HTML reports have a `score` column type (a percentage coloured by the same thresholds).
- the HTML reports can show a hierarchy tree (`Write-AACHtmlReport -Tree`), drawn a level at a time so large tenants stay fast.
- `Show-AACResourceMap -SubscriptionId ... -ResourceGroupName ...` - a map of one or more resource groups, in one or more subscriptions, opened in your browser. Each resource has its official Azure icon, its name, its product and a detail worth seeing (a VM's size, an IP, a disk's size), in boxes: subscription > resource group > virtual network > subnet. A resource with an IP in a subnet (NIC, private endpoint, firewall, gateway, Bastion, internal load balancer, AKS, API Management) is drawn in it, and a VM in the subnet of its NIC; each subnet names its NSG, route table and NAT gateway. The connections come from the resource IDs in each resource's properties and are drawn by kind: network association, resource dependency, VNet peering (with its state), private link, route (a route table to the firewall or appliance its next hop is, e.g. `0.0.0.0/0 -> 10.0.1.4`) and private DNS link. Resources outside the selection that a chosen one uses are drawn in their own resource group's box, marked as such; resources attached to nothing (a NIC without a VM, a public IP without a configuration, an unattached disk, an NSG or route table on nothing) are flagged. The page is one self-contained file laid out by the Eclipse Layout Kernel (`elkjs` 0.12.0, EPL-2.0, vendored and hash-checked): pan and zoom, click to highlight a resource's connections with its details and a portal link, search, left-to-right or top-to-bottom, Dark, Light and Blueprint themes, show or hide each kind of connection, and **Save PNG** / **Save JPEG** (twice the screen's resolution) or SVG. `-Direction`, `-Theme`, `-ExcludeType`, `-HtmlPath`, `-NoBrowser`, `-PassThru` (the resources and connections as objects). Uses Microsoft's Azure architecture icons (V21) under Microsoft's terms for architecture diagrams.
- in the resource map, NSGs and route tables as a network engineer reads them. Each is a chip on the subnets and NICs it's applied to, and a click shows its rules or routes:
  - **NSG:** inbound and outbound rules by priority, application security groups by name, default rules folded away.
  - **Route table:** each route with its next hop resolved to the resource that owns the IP, and whether gateway route propagation is off.
  - **Colours:** red for an NSG that opens every port, or a management or database port, to the internet, or for a route whose next hop no resource has (the traffic may be dropped); amber for a wide port range open to the internet, or `0.0.0.0/0` straight to the internet.
  - **Routes from the subnet:** a subnet's routes are drawn from the subnet to the firewall or appliance they go through (`0.0.0.0/0 via rt-spoke`); next hops outside the selection are looked up in every subscription you can see, so a spoke's map reaches the hub firewall.
  - **Subnets and peerings:** each subnet shows its IP usage (`3 of 251 IPs used`) and delegation; each peering shows forwarded traffic, gateway transit and remote gateway.
  - **Filters and views:** "show only what's flagged", and `-NsgView Cards` (or the page's switch) for NSGs and route tables as resources with lines. `-PassThru` objects carry `Risk`, `AppliedTo`, `Rules` and `Routes`.
- `Invoke-AACApplicationInsightQuery -TableName` reads any table, not only the exceptions: `requests`, `dependencies`, `traces`, `customEvents`, `pageViews`, `availabilityResults` and the rest, or a workspace's own tables. Either schema's name works for either source (`requests` on a workspace reads `AppRequests`), and Tab completes them. `-Last`, `-AppRoleName`, `-Search` (any column) and `-MinimumSeverity` (traces) filter them. The view is a table of the rows with the table's most useful columns first, and the objects have every column. A filter the table can't take is refused with the reason.
- when a table doesn't exist, the error panel names the tables the source has, closest names first ("Did you mean 'requests'?"), with how many rows each has in the period - from the query API's metadata.
- errors shown with Spectre.Console. When a command fails at the console, the progress line of the step that was running turns red ("- failed"), and a red panel shows what failed, that step, and what to do - sign in again, the role needed (403), check the name (404), throttling (429), the network, a file open elsewhere. Every command then stops with its own clean error (`Show-AACCost: ...`), pointing at the caller's line rather than a line inside the module, with an error ID (`AzureRequestFailed403`, `InternalError`, `CommandFailed`) and category for scripts; there's no panel in scripts' non-interactive output or with `-ErrorAction SilentlyContinue`. An error that is a bug in the module says so, with the module file and line and where to report it.

### Changed

- a subscription with no cost in the period is now a state of its own rather than an empty "(no currency)" section: its `Status` is `No cost`, it's left out of the charts and totals, and it's listed - a grey line at the console ("sub-dev: no cost since Apr 2026"), a tile and an info note in the HTML report, a "Subscriptions with no cost in this period" table in the PDF. ### Fixed

- `Show-AACCost -PdfPath` failed with "The property 'Count' cannot be found on this object" when a subscription had no costs at all. Such a subscription has no billing currency, so the PDF gave it a summary of its own - with no services or resource groups, which the top-services table didn't allow for.
- `Invoke-AACApplicationInsightQuery` failed with the same error when the query returned no rows (a quiet workspace, a short `-Last`, filters that match nothing). It now returns nothing and shows the empty view.
- `Get-AACFirewallRule -SourceAddress`, `-DestinationAddress` and `-Fqdn` missed a rule with exactly one address and exactly one IP Group address (or one destination and one target FQDN): the two were joined as one text (`10.0.0.110.1.0.0/16`) instead of a list of two.
- `Invoke-AACApplicationInsightQuery` queried through an Azure Resource Manager route that isn't registered: `-ApplicationInsightsName` failed with "No registered resource provider found for location ... and API version '2018-04-20' for type 'components/api'". It now uses each service's documented query API - `api.loganalytics.azure.com/v1/workspaces/{workspace ID}/query` and `api.applicationinsights.io/v1/apps/{app ID}/query` - with a token for that API taken from the `Connect-AAC` sign-in's refresh token (no second sign-in; kept per API until it nears expiry). A query error now shows the query API's own reason, innermost detail included ("Failed to resolve column ..."). An App Registration of your own (`Connect-AAC -ClientId`) needs the delegated Data.Read permission of both APIs.
- `Invoke-AACApplicationInsightQuery -LogWorkspaceName` returned "no exceptions" without saying why. A workspace only holds the exceptions of the Application Insights resources that send to it. When it has none, a warning now names those resources, or - if none send there - lists the ones you can see, where each sends its data, and the `-ApplicationInsightsName` command to query one directly. A reply from the query API without a result table is now an error instead of an empty result, and `-Verbose` shows the endpoint, timespan and KQL.
